# Revex terminal TUI redesign

## Intent

The previous launch screen was a printed banner followed by `1/3 API base URL` and a line-based REPL. The user tried it and rejected it as unlike Claude Code. Interactive Revex should instead be a persistent keyboard-operated terminal UI from launch through setup, conversation, agent inspection and approval.

## Screens and behavior

- Use an alternate-screen TUI with a compact conversation screen that keeps Revex's own identity. The user's Codex launch example is a reference for clear input focus and visible workspace/model context, not a visual template to copy. The top shows `Revex v<package version>`, the selected model with its explicitly configured reasoning effort, and the workspace path on separate lines. The bottom keeps a prominent input and sparse command hints without repeating the model or path. The transcript scrolls without moving the input and shows tool activity, answers and errors. While a model request is active, a bounded status indicator makes waiting/generation visible without adding routine progress lines to the transcript. Fenced code in replies and code in edit previews receive syntax highlighting.
- On first launch, show a focused setup screen in the same TUI. Arrow keys select Ollama, LM Studio, oMLX or a custom OpenAI-compatible API. oMLX defaults to `http://127.0.0.1:8000/v1`. Each preset exposes its URL as an editable value; do not imply the server is running. The API key is optional and masked. Changing the URL must not send a saved key to the new endpoint without an explicit choice to reuse it. Query `/models` with a short timeout and offer a model picker when available, plus manual entry. Show connection results and let the user retry. Save only confirmed settings to private `~/.revex` and continue to chat.
- Setup and `/config` also let the user select one or more helper-agent providers: the local API, Codex CLI, and Claude Code CLI. The default is local. Save the selection in private user settings; never let an untrusted project settings file select an external executable. When multiple providers are enabled, `>> spawn TASK` distributes starts across the enabled providers, and an explicit provider selector may override that choice. `/agents` shows the actual provider for every child. Codex helpers run with the user's authorized YOLO option and Claude Code helpers with Bypass Permissions, without per-task approval prompts. Failed starts remain failed rather than silently switching providers. On Revex exit, active external child processes are stopped and reaped.
- On first use of a canonical launch directory, show its exact path and ask whether to use it as the workspace before loading/saving project history. Confirming uses that directory for both tools and history and privately remembers the answer, so later launches from the same workspace open without another confirmation. A different workspace asks once. Declining exits with guidance to change directory and restart; the screen does not ask for another path. This applies when launched from `target/release` too.
- After workspace confirmation, configured launches enter the chat screen directly; no extra `start >` prompt. `/config` opens an editable settings overlay. `/model` loads the model list, lets the user select a model or server default, and then an optional reasoning effort; the chosen effort is persisted and sent in subsequent Chat Completions or Responses requests. `/agents` opens a live table of parent and child status, task and provider-reported input/output tokens. `/status` shows current connection and session details. Esc closes overlays.
- Approval requests interrupt input with a modal showing the command or bounded edit preview. An edit preview must show both old and proposed text, with scrolling when needed. Arrows or Tab select Deny/Approve; Enter confirms and Esc denies. Only fresh key events after the modal opens can approve. The pending request cannot be lost behind `/agents` or another overlay.
- The UI handles resize, narrow terminals, scrolling and common keyboard editing. The active URL, masked API key, manual model and chat input show a visible insertion cursor that tracks edits without revealing secrets. Ctrl+C interrupts the current task safely; Ctrl+D, `/exit` or plain `exit` exits and restores the terminal. Existing shell cancellation and child interruption rules remain in effect.
- Up/Down in the chat editor recalls the latest 100 sent inputs per workspace across restarts and `/clear`; Down past the newest entry restores the draft. User messages have a subtle background and one blank line above and below each message block; assistant replies have the same one-line spacing. A simple question about the current model is answered directly from the effective configuration without calling a model or tools, opening files, or exposing the API URL/key. The model also receives the configured ID and reasoning effort as request metadata for wider questions; an omitted model remains server-selected/unknown.

## Implementation boundaries

- Use `ratatui` and `crossterm` for terminal rendering and input. Reuse the current agent manager, model loop, persistence, approval channel and tool protocol. Keep one-shot, piped and MCP modes free of ANSI output and setup prompts.
- Terminal entry/exit must restore raw mode, cursor and alternate screen on success, error, signal and panic. Release uses `panic = abort`, so install a restoration hook or equivalent.
- Normal TUI output goes through a transcript/event sink. Existing direct stderr writes must be routed or captured so they cannot corrupt the screen. Never call model discovery or another blocking network operation from the draw path.
- If stdin is a TTY but the output is redirected, use a plain fallback or clear error without escape sequences.

## Completion evidence

- Pure UI tests cover setup state transitions, provider selection, masked key, model picker/manual model, workspace confirmation, `/agents`, approval and resize including tiny terminal sizes.
- PTY checks show first-run and configured screens, keyboard selection, workspace confirmation/decline, terminal restoration after exit/Ctrl+C, and a live `/agents` during a blocked fake SSE request.
- Existing Rust tests, Clippy, formatting, release build and one-shot/piped/MCP smoke checks still pass. A real model server is not configured here, so live model quality remains unverified.
