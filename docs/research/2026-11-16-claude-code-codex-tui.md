# Claude Code and Codex terminal behavior relevant to Revex

Checked on 2026-11-16 for the Revex terminal redesign. The installed Mac commands report Claude Code `2.1.325` and Codex CLI `0.169.0`. Codex's public source at tag `rust-v0.169.0` was inspected alongside Claude Code's official documentation. Claude Code's installed binary is closed source; binary strings were treated only as clues, not proof of behavior. No private settings, credentials or conversation files were inspected.

| Area | Reference behavior and evidence | Revex state |
| --- | --- | --- |
| Input recall | [Claude Code command history](https://code.claude.com/docs/en/interactive-mode#command-history) persists per working directory and includes reverse search. [Codex composer history](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/bottom_pane/chat_composer_history.rs) navigates at editor boundaries and preserves the in-progress draft. | Up/Down recall, draft restoration and the latest 100 sent inputs persist per workspace across restarts and `/clear`. Ctrl+R reverse search remains a gap. |
| Editor and queue | [Claude Code interactive controls](https://code.claude.com/docs/en/interactive-mode#keyboard-shortcuts) distinguish multiline cursor movement from history navigation, and [queued messages](https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works) remain visible while a turn runs. | Revex accepts multiline input and queues tasks while the model works. The editor does not yet defer history navigation until the first or last visual row, or show a separate editable queue. |
| Direct shell entry | [Claude Code shell mode](https://code.claude.com/docs/en/interactive-mode#shell-mode-with--prefix) executes input prefixed with `!` from the composer. | Revex lets the model run approved `>> sh` tool calls. A user-facing `!` shell mode is not implemented. |
| Model selection | [Claude Code model configuration](https://code.claude.com/docs/en/model-config) exposes model and effort choices. | `/model` fetches available IDs, accepts manual entry or server default, then offers optional effort. The request carries configured model and effort metadata so an identity answer can report them without claiming an unknown underlying model. |
| Conversation display | [Codex Markdown renderer](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/markdown_render.rs) renders fenced code with language-aware styling. | Revex separates message blocks, shades user input, highlights common fenced-code languages and indicates active model work without routine status lines in the transcript. |
| Agent visibility | [Codex agents overview](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/app/agents_overview.rs) provides an in-terminal agent list. | `/agents` shows each helper's provider, task, status, model when known, and reported token counts. Setup can enable local, Codex and Claude Code helpers together. |
| Approvals and terminal state | [Codex approval overlay](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/bottom_pane/approval_overlay.rs) and [terminal lifecycle](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/tui.rs) isolate approval input and restore terminal state. | Revex uses a focused modal for tool approvals and restores the terminal after normal exit, interruption and error. |
| Sessions | [Codex resume picker](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/resume_picker.rs) and Claude Code's [resume flow](https://code.claude.com/docs/en/interactive-mode) support selecting a prior session. | Revex restores one conversation per canonical workspace. Choosing among multiple sessions in the same workspace remains a gap. |

These are feature comparisons, not a claim that Revex reproduces either product. In particular, token counts depend on provider usage data; Revex cannot infer counts that the provider omits. A configured model ID may be an alias and does not reveal the server's underlying weights. The local model server used by the user was reachable but required authentication during an unauthenticated probe; no authenticated inference test was performed.
